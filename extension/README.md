# Chrome extension

Popup использует общие CSS, Nuxt UI configuration, строки задач и форму остановки
Dashboard. Таймер общий для сайта и расширения в одном профиле Chrome; его состояние
координирует MV3 service worker. Дополнительного поиска и миграций старого таймера нет.

## Настройка и сборка

1. Расширение подключается к [Dashboard](https://yandex-tracker-dashboard-fork.vercel.app).
   Адрес, public manifest key и стабильный extension ID находятся в
   [config.json](config.json). При изменении адреса меняйте этот единственный
   источник и пересобирайте сайт и расширение. Для локальной разработки можно
   указать `http://localhost:3000`.
2. Укажите публичный OAuth client ID через существующий `NUXT_PUBLIC_YANDEX_CLIENT_ID`
   или отдельный `EXTENSION_YANDEX_CLIENT_ID` при сборке расширения. Секретный ключ
   клиента не нужен и не должен попадать в пакет.
3. В настройках Yandex OAuth зарегистрируйте Redirect URI:
   `https://iillbhjmnnpdjflfhlmdclakhpjilanp.chromiumapp.org/`.
   Для входа на сайте форка добавьте `https://yandex-tracker-dashboard-fork.vercel.app/auth`.
   Используются authorization code, PKCE S256 и state. Клиенту нужны доступы к
   Tracker, профилю и аватару, как для Dashboard. Готовность конкретного client/scopes
   проверяется отдельно на разрешённом тестовом контуре.
4. Подготовьте зависимости и Nuxt types, затем выполните:

   ```sh
   pnpm extension:typecheck
   pnpm extension:build
   ```

5. Откройте `chrome://extensions`, включите режим разработчика, выберите
   «Загрузить распакованное расширение» и каталог `dist-extension/`.
6. Откройте Dashboard и войдите в нём. При первой связи расширение получает тему,
   настройки виджета и ID организации для того же Яндекс-аккаунта. Затем войдите
   в popup через Яндекс; если организация ещё не получена, её ID можно ввести вручную.

Для запуска Dashboard используется существующий `pnpm dev`. Его `/tracker` proxy
по умолчанию обращается к настоящему API: локальный адрес frontend не является
изоляцией backend. Проверки с данными выполняются только на согласованном test
upstream, без production доступа.

## Vercel

Fork подключён к проекту `yandex-tracker-dashboard-fork`: framework Nuxt,
Node 24, установка `pnpm install --frozen-lockfile`, сборка `pnpm build`.
Каждый push в `master` запускает Production deployment через Git integration.
Для Production и Preview нужен публичный `NUXT_PUBLIC_YANDEX_CLIENT_ID`; OAuth token
и client secret в настройках Vercel не нужны.
Для API расширения Dashboard должен отвечать без Vercel Login: запросы отправляются
без cookies. Доступ к данным Tracker по-прежнему требует пользовательский OAuth token.

## Поведение

- Профиль открывает меню Dashboard / Настройки сайта / Выйти.
- Виджет повторяет сайт: роли, статусы, поля, сортировка, пять задач на странице,
  обновление и ссылка «Все». При работающем таймере второй старт отключён.
- «Стоп» открывает общую форму с длительностью, комментарием и сменой статуса.
  Закрытие popup сохраняет черновик, отсчёт продолжается от startedAt.
- Выход очищает только авторизацию расширения. Таймер продолжает работать;
  сайт и повторный вход владельца могут им управлять.
- Настройки сохраняются локально после связи с сайтом. Изменения сайта приходят
  по активному соединению или при следующем подключении.
- При разрыве связи сайт показывает последний подтверждённый read-only mirror;
  запись разрешена после нового handshake. Автоматического failover при удалении
  или отключении расширения нет. Восстановите расширение для управления общим таймером.
- Старый ключ таймера сайта не читается для импорта, не перезаписывается и не удаляется
  общим режимом. Расширение начинает с отдельного owner-scoped состояния.
- Неопределённый исход POST блокирует автоматический повтор. «Проверить сохранение»
  ищет совпадающую запись текущего владельца. Если записи нет, сначала проверьте
  трудозатраты задачи в Tracker; «Я проверил: записи нет» только снимает блокировку,
  после чего сохранение запускается отдельным нажатием. Не подтверждайте отсутствие
  записи без ручной проверки: при ошибочном решении возможен дубль.
- Неудачная смена статуса после успешной записи показывает warning и не повторяет
  создание worklog.

Удаление расширения удаляет его Chrome storage. Перед удалением завершите активный
таймер; backup более нового состояния, чем последняя связь с сайтом, не гарантируется.

## Проверки и границы

`pnpm typecheck`, `pnpm lint:fix`, отдельный `extension:typecheck`, сборка пакета
и существующие тесты запускаются из корня. Новые test suites не добавлены.
В локальном Chrome проверены вход сайта и popup, первичная синхронизация настроек
и задач, ширина 480 px и повторное открытие с восстановлением сессии.
Запись времени, изменение настроек при активной связи и полная проверка browser
lifecycle/race/error-сценариев остаются отдельными acceptance gates.
Публикация в Store не выполняется.

Официальные контракты: [Chrome Identity](https://developer.chrome.com/docs/extensions/reference/api/identity),
[Yandex OAuth/PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url).
